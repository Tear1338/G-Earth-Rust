# Native extension store

The Extensions tab includes catalogue loading, text search, rating/alphabetical/date ordering and operating-system, client, framework and category filters. It uses beta-29's original sirjonasxx/G-ExtensionStore catalogue version 1.5.3. Outdated entries are optional. Source, readme, release and framework-installation links are available for each entry.

Core store controls and sorting choices are translated into French and English; catalogue content and some status messages remain in their original language. While the store panel is displayed, it requests periodic repaints during background operations so results can appear without user input. Local translation tests and desktop compilation pass; actual UI interaction and network loading remain unverified.

Install downloads and extracts the selected package on a worker. Archives, member counts and expanded bytes are bounded; absolute paths, traversal and symlinks are rejected. Failed extraction removes only its verified staging directory. Installation manifests record version, command and archive SHA-256. The launch command is taken from the matching entry in the loaded catalogue, rather than from a separate caller-provided copy. Downloads do not launch the package. The manifest and installed files remain writable locally; this does not verify package authenticity or protect against later modification.

Updates install a new version beside the previous one. The install button compares the catalogue entry with the newest installed version from the same source and identifies an older catalogue version separately. Installed versions have separate Launch and Uninstall controls. Launch expands the original port, filename and cookie placeholders and uses the one-use authenticated extension channel. Java entries use the configured Java runtime. Other framework runtimes must be installed separately. Runtime output appears in the extension console.

Uninstall verifies the manifest and resolved managed installation directory. It does not select other installed versions. This path does not migrate or delete older Java G-Earth installations.

Fixtures cover searching/filtering, chronological ordering, versioned installation, failed-extraction rollback and managed-directory deletion. CI parses a pinned 105-entry original catalogue and authenticates the actual Java API fixture through the store command launcher. Version ordering uses Maven's nested qualifier and numeric rules and is checked against the Maven JAR bundled with beta-29 across 2,304 version pairs. Inputs over 512 bytes use a bounded lexical fallback. Thumbnails, embedded readme rendering and legacy store presentation details remain incomplete.
