# Continuation state

The requested goal is a complete Rust replacement for G-Earth 1.5.4-beta-29, with original functionality and a GitHub project. The repository is Tear1338/G-Earth-Rust. It remains a development port; do not describe a passing component test as whole-application parity.

The upstream reference remains commit `242155c291b1109d6c9a02370f6a2af1ead41ea8`. Read PARITY.md, UNITY.md, STORE.md, GPYTHON.md, ATTACHMENT.md, FLASH_VALIDATION.md and VALIDATION.md, then inspect the current working tree and latest Actions run before changing code. External edits may have occurred since this note.

Implemented foundations include EVA/WEDGIE packets, expressions, RC4/Origins crypto, bounded relay, rules/schedules, settings/languages, packet providers/cache, a Java-compatible extension host, Windows Flash negotiation and read-only memory discovery, TCP-owner process selection, scoped hosts routing and Flash Raw-IP mapping with preconnected upstreams. Native memory and proxy tests use a controlled child process, isolated test registry keys and temporary files. Raw-IP tests mock every privileged command and use real loopback sockets; no real hosts entries, loopback aliases or NAT rules were changed during development tests.

Nitro now has a Rust HTTP/TLS/WebSocket backend, strict upstream certificate verification, shared logger/rules/injections/scheduler/extensions and a desktop connection mode. Dynamic nitro.json has precedence over the beta-29 built-ins and supports final-* URL prefixes after query stripping. Hubbe, HabboSK, Hartico and HabboCity adapters are ported. Windows has explicit current-user certificate buttons, exclusive proxy ownership and a binary recovery journal; isolated HKCU test fixtures cover restoration and interrupted ownership. Nitro Helper uploads require an unsaved session opt-in, and tests never upload anything. Read NITRO.md. Chrome TLS fingerprint emulation, Nitro upstream SOCKS routing, real hotel regression and non-Windows proxy/trust helpers remain missing. An HTTP/WebSocket fixture and the actual beta-29 Java extension exercise the shared pipeline; five independent Java JCE vectors cover the hotel cryptography.

Unity now has the communicator, TLS/session authentication, HTTP asset interception, framework/loader injection and validated WASM rewriting. It is connected to the desktop. Read UNITY.md. The original Java patcher and Rust output pass the same execution assertions. A Node browser-hook fixture traverses real WSS and Rust rules/injections; actual Java extensions are tested for Unity as well as TCP/Nitro. The released G-Presets 1.6.5 has authenticated in an isolated fixture; official production-client and G-Presets game sessions remain untested.

The native extension store now implements catalogue search/filter/order, bounded ZIP installation, side-by-side updates, authenticated commands and managed uninstall. Read STORE.md. Maven-style version ordering has finite differential coverage against the original Maven JAR; presentation details remain. The host launcher captures bounded runtime output.

The live Python console now has a Rust launcher, dependency checks, explicit cancellable package installation/repair, Jupyter kernel setup, QtConsole launch and bounded process ownership. Real published G-Python 0.1.6 fixtures pass authentication, named injection, bidirectional modification/blocking and kernel shutdown on Linux and Windows. The installer fixture uses an isolated virtual environment; do not run it against a developer's global interpreter. Read GPYTHON.md. Do not use the upstream main archive as the oracle: its circular imports fail before connection.

The scheduler supports finite and explicitly indefinite jobs, per-job pause/resume/removal, editing active jobs by stable identity and editable saved templates. Optional Windows global Ctrl+Shift+0–9 shortcuts toggle the first ten jobs; conflicts are reported and owned registrations are released on disable/exit. Linux/macOS global shortcuts and interactive physical-key/minimized-window validation remain missing; see HOTKEYS.md. Editing a running job preserves its pause state and leaves templates unchanged. Jobs are retained during a transient disconnection and resume on reconnection; explicit Stop still clears them. An enqueue failure does not consume the failed repetition, but an accepted queue item is not proof that the remote received it. It imports and exports beta-29 tab-separated `.sched` files, preserving packet text, direction, offset and paused state; import replaces templates but never starts jobs. Export rejects finite or relative templates that the Java format cannot represent without changing behavior. Editing a template does not change active jobs; changes require saving settings. An optional offset aligns sends to the Unix clock and detects clock changes above a tolerance of the smaller of 20 ms or half the interval; it recalculates the next future deadline, skips missed sends and keeps relative jobs unaffected. It rejects an offset equal to the interval (the Java UI accepts that value but it never matches a timestamp). The upstream scheduler can replay missed deadlines while the Rust implementation deliberately avoids bursts. Exact persistence semantics remain. Other missing areas include real firewall/alias and Raw-IP multi-instance client validation, non-Windows privileged helpers, QtConsole visual validation, exact UI/shortcuts/tray behavior, full localization and validation with real client sessions and G-Presets. Whole-application performance remains unmeasured; PERFORMANCE.md covers only packet construction.

Starting saved schedules validates every expression and schedule before adding any of them. A failure leaves existing active jobs untouched and reports that none of the saved schedules started; a successful batch preserves each template's pause state. Local Windows GNU tests cover batch rollback, identity allocation and paused jobs, and the desktop compiles. Automatic restoration after restarting the application remains unimplemented.

The desktop now requests its next update according to the earliest unpaused scheduler deadline, capped at the normal 50 ms event-poll interval and with a 1 ms minimum retry for already-due jobs. This removes the previous unconditional 50 ms wakeup request for short intervals. It is a scheduling hint, not a timing guarantee: actual dispatch remains on the UI thread and depends on OS/window-system scheduling, frame rate and queue availability. Local deterministic tests cover deadlines, pauses and due-job retries; no real-time latency or minimized-window benchmark has been performed.

The pinned beta-29 SchedulerController creates a fresh scheduler and loads or saves `.sched` files explicitly; no automatic restart restoration is present in that controller. The desktop provides **Load and replace active** for connected sessions: it parses the entire selected file and compiles every packet before atomically replacing the active jobs. Invalid input leaves jobs and templates untouched; an empty valid file clears active jobs. Loaded pause states and aligned offsets are retained. This action does not replace saved templates; regular Import continues to edit templates separately. **Export active** writes current jobs including edits and pause state independently of **Export templates**. Active jobs retain their original packet expressions for editing and export, including symbolic names; jobs created without source text fall back to Java-compatible byte notation. A named expression may resolve differently if packet identifiers change before the file is loaded again. Export rejects finite, relative or sub-millisecond jobs that `.sched` cannot represent without changing behavior. Both exports replace their destination after a complete temporary write. Byte-for-byte fallback roundtrips through the released Java API were tested for EVA and both WEDGIE formats, with all byte values; this is finite compatibility evidence. The UI and real user files have not been interactively validated.

The Windows local test environment denied replacement inside its sandbox-provided temporary directory; the atomic export test passed when TEMP and TMP were redirected to the workspace build directory. This is an environment-specific observation, not validation of every destination filesystem.

The transient rule editor compiles only when enabled. An invalid draft is omitted from the rules sent to the active connection, while saved rules are still installed and the error is displayed. This prevents a previously valid transient replacement from remaining active after its text becomes invalid and permits disabling it even with an invalid draft. Enabled saved rules are also compiled individually for the selected client format; invalid rules are skipped and identified beside the relevant row while other valid rules are installed in their original order. Disabled rules do not prevent updates. Invalid Shockwave header IDs (outside 0–4095) are reported for both saved and editor rules. Changing client mode revalidates the rules. Local Windows tests cover incompatible Shockwave replacements and IDs, preserved block/replace behavior, disabled entries, and desktop Clippy. Installing a new ruleset can still fail if the connection's rule lock is poisoned; in that case the error is reported. Physical UI interaction and live hotel traffic were not tested.

Saved rules can now be edited or moved up/down in the injection panel. Editing retains the saved rule's enabled flag and position, does not modify the active rule until submitted, and disables the transient editor rule while editing. Reordering is disabled during an edit, and removing another row adjusts the selected index. Changes are applied to the running connection and saved with the application settings; the test fixture verifies a concrete order-dependent block/replacement case, invalid indices, persistence, and retained disabled state. UI interaction and real traffic remain untested.

Native Rust parsers now cover room entities, movement, floor/wall furniture, inventory pages, all eight furniture state variants, profiles/friends, catalog, navigator and forum overviews. The released Java API supplies finite packet and decoded-value comparisons for state formats, furniture, friends, catalog, navigator and a forum comment. The original Java inventory page constructor has edge-case pagination defects; Rust uses complete pages of at most 600 items. The remaining parser APIs need implementation and wider differential tests. EVA packet mutations include typed fixed-width fields, one string, bulk exact strings and integers, with finite Java comparisons of packet bytes and cursor. Explicit UTF-8 short and long string operations and UTF-8 replacement are also checked against selected Java examples. Raw short and long length-prefixed fields allow caller-provided charset encoding and are compared with Java UTF-16BE examples. UTF-8 decoding is strict and restores the cursor on invalid input, unlike Java's replacement decoding; other charsets do not have built-in codecs. The Latin-1 mutation helpers reject header writes, malformed input, unsupported WEDGIE mutations and non-Latin-1 text; a cursor past a shortened packet is clamped, whereas Java may leave it out of bounds. The Java replacement can corrupt the byte after an empty string when growing it; Rust preserves that following byte, covered by a regression test. Substring/regex and other charset helpers remain unimplemented.

Structure prediction now ports the beta-29 heuristics for classic and Unity packets, with bounded scan/expansion and nested metadata structures. Extension packet-to-string requests and the logger use known structure when available and prediction otherwise. The logger has saved options for additional packet data, separators and lazily rendered expressions; it invalidates cached expressions on metadata updates. WEDGIE prediction is unavailable. Differential checks against the original Java API cover 24 prediction samples, selected nested/number expressions and direction-specific metadata with duplicate identifiers. Larger or unusually costly input is bounded and can yield an empty expression.

The logger now includes the original five anti-spam levels, applying thresholds of 15, 9, 4 or 2 incoming messages per header over five seconds; blocked, edited and outgoing messages are exempt. Filtering affects only display and capture export, never forwarding. A mode change clears filter history; unlike the original, the disabled mode stores no timestamp history. The filtered count is displayed and cleared with the log. Optional packet names and hashes use direction-specific metadata, deduplicate values, invalidate caches on metadata refresh, and count bounded cache allocations against the log budget. The logger also marks edited packets as replaced. Local tests cover thresholds, expiry, exemptions, names and cache invalidation; UI appearance and live traffic remain untested.

The logger additionally offers selectable Expression, Legacy and Raw hex display, optional Unix-millisecond timestamps and an auto-scroll toggle, with settings persisted. Legacy and hex display format a maximum of 1024 bytes per visible row and mark truncation; the original captured packet and existing lossless expression remain intact for injection. Timestamps are recorded when the desktop processes each packet event, not at the network receive instant. The original logger's complete layout and behavior remain unfinished. Local byte-format tests and Windows desktop Clippy pass; visual behavior remains untested.

The displayed-capture export now shares row formatting with the on-screen logger and respects the current direction/search filters, representation, timestamps, metadata, structure and separator options. Its text preserves full generated lines rather than the window's width-based clipping, and applies the same representation size limits as the display. This replaces the earlier Rust-only tab-separated capture format; it is not a lossless capture format. Tests cover metadata, timestamps, blocking, raw hex, hexdump and write errors. Exact formatting against the original Java text area and interactive use remain unverified.

Displayed-capture export now writes to an exclusively created temporary file beside the destination, flushes it and replaces the destination only on success. A local Windows test confirms that a simulated partial-write error keeps the previous capture and removes the temporary file; behavior across all filesystems is not established.

The logger also offers a persisted inline Hexdump mode. It renders up to 128 bytes per packet, explicitly marks truncation and leaves the packet intact; the separate inspection window shows up to 4096 bytes. Hex formatting and settings roundtrips have local tests, but the layout and interaction have not been visually checked against the original.

The logger additionally allows Legacy, Raw hex and Hexdump to be shown together through independently persisted additional-representation controls. The existing main representation setting remains compatible. Duplicates are suppressed, the display and export use the same selected representations, and length limits still apply; a local test covers simultaneous output. The control layout and exact Java visual parity remain unverified.

The logger has a separate, localized message ID checkbox, persisted alongside name and hash choices. After editing an active scheduler entry, cancelling its edit or removing it, the editor clears its text and returns to the original 500 ms incoming defaults. The same reset occurs if active jobs are cleared or replaced while editing. These UI paths compile and existing desktop tests pass; no interactive visual test has been performed.

The tools panel also provides signed 32-bit and unsigned 16-bit encode/decode using the original byte display convention; boundary and malformed-input tests pass. Injection accepts up to 256 expressions per batch, keeping newlines inside quoted fields, and validates the entire batch before queueing any packet.
