EVA packets can now test whether their complete body matches a typed structure, including count-prefixed groups, without changing packet data or cursor. A finite Java oracle checks nested, incomplete, empty and invalid examples, including unknown symbols where Java stops interpreting the current group. Parsing and expansion are bounded, which may reject exceptionally large structures accepted by Java. WEDGIE and real extension sessions remain unvalidated.

The EVA packet API now supports beta-29 `HPacket.skip` structure codes for integers, strings, bytes, booleans, shorts, longs and doubles, ignoring unknown characters. Normal cursor results are compared with the released Java API. On truncated input Rust retains the cursor after the last successful field; Java can advance beyond the packet on a failing byte read, so that error case is deliberately different. WEDGIE skip and real extension usage remain untested.

EVA packets now expose a fixed-length `replace_bytes` operation that preserves the read cursor. A finite byte comparison against beta-29 HPacket covers a normal body write; tests also check bounds and rollback. Unlike Java's `replaceBytes`, which truncates an oversized write at the packet end and can touch header bytes, Rust rejects writes outside the body atomically, consistent with its other typed mutations. WEDGIE and live client behavior are not covered.

The packet API also exposes absolute-offset reads without moving the read cursor. EVA supports bytes, booleans, numbers and Latin-1 short and long strings; a finite beta-29 Java oracle checks values, header access and cursor preservation. WEDGIE supports bytes, VL64 integers/booleans, unsigned shorts and short strings, matching the port's sequential decoding, with tests for both directions and invalid input. These WEDGIE helpers intentionally decode the wire format; beta-29 HPacket's offset numeric methods read fixed-width bytes instead. WEDGIE long strings, floats and 64-bit integers remain unsupported and real clients unvalidated.

The scheduler supports finite and explicitly indefinite jobs, per-job pause/resume/removal, editing active jobs by stable identity and editable saved templates. Optional Windows global Ctrl+Shift+0–9 shortcuts toggle the first ten jobs; conflicts are reported and owned registrations are released on disable/exit. Jobs are retained during a transient disconnection and resume on reconnection; explicit Stop still clears them. An enqueue failure does not consume the failed repetition, but an accepted queue item is not proof that the remote received it. It imports and exports beta-29 tab-separated `.sched` files, preserving packet text, direction, offset and paused state; import replaces templates but never starts jobs. Export rejects finite or relative templates that the Java format cannot represent without changing behavior. Editing a template does not change active jobs; changes require saving settings. An optional offset aligns sends to the Unix clock and detects clock changes above a tolerance of the smaller of 20 ms or half the interval; it recalculates the next future deadline, skips missed sends and keeps relative jobs unaffected. It rejects an offset equal to the interval (the Java UI accepts that value but it never matches a timestamp). The upstream scheduler can replay missed deadlines while the Rust implementation deliberately avoids bursts. Exact persistence semantics remain. Other missing areas include real firewall/alias and Raw-IP multi-instance client validation, non-Windows privileged helpers, QtConsole visual validation, exact UI/shortcuts/tray behavior, full localization and validation with real client sessions and G-Presets. Whole-application performance remains unmeasured; PERFORMANCE.md covers only packet construction.
